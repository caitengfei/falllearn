# 学生批量使用与隐私保护方案

> 面向：任课教师（发号、看数据）与学生（注册、使用）
> 结论放在最前：**用「邀请码自助注册」**——教师生成一个班级邀请码，学生在注册页填「邀请码 + 昵称 + 自设密码」即可使用；全过程不采集手机号、邮箱、身份证、学籍号，学号由平台自动分配。

---

## 一、三种加入方式对比

| 方式 | 教师操作 | 学生操作 | 隐私采集 | 适用 |
|---|---|---|---|---|
| **① 邀请码自助注册（推荐）** | 生成邀请码 → 发到班级群 | 打开链接，填邀请码、昵称、自设密码，30 秒完成 | 仅昵称（可用昵称） | 整班批量使用；学生手机/电脑都能注册 |
| ② 批量发号（已有功能） | 生成 N 个账号密码 → 打印或发群 | 用教师发的账号密码登录 | 教师指定的姓名模板（如「同学01」） | 无手机、需统一口令的场景；教师需逐个分发 |
| ③ 单个建号 | 逐个新建账号 | 同上 | 同上 | 零星补号、转学生 |

三者可混用：例如先发邀请码让多数学生自助注册，少数没成功的用批量发号补。

## 二、教师三步操作

1. **登录教师端** → 侧栏「账号管理」→ 顶部绿色卡片「🎟 邀请码 · 学生自助加入」→ 展开；
2. 填备注（如「2026 级养老 1 班」）、人数上限（默认 60）、有效期（默认 30 天）→ 点「生成邀请码」；
3. 得到 `FD-XXXXXX` 与注册链接 `http://<服务器>/register?code=FD-XXXXXX`：
   - 点「复制链接」发到班级群（学生点开即进入注册页，邀请码已自动填好）；
   - 或用任意二维码工具把链接生成二维码，投屏/打印在教室；
   - 「复制码」只复制 6 位邀请码，学生也可在登录页「老师发了邀请码？用邀请码加入」手动输入。

**管理**：邀请码列表显示每个码的「已用 / 上限、有效期、状态」，可随时**停用/启用/删除**；学生注册后若需清退，在下方账号表删除该学生账号（连带其学习数据）。

## 三、学生两步操作

1. 打开链接（或登录页 →「用邀请码加入」）→ 填邀请码（链接进入会自动填）；
2. 填**昵称**（可写姓名，也可写昵称）、**自设密码**（≥6 位）→ 点「注册并进入」→ 直接进入学习首页，无需再登录。

> 忘记密码：请老师重置（账号管理中「重置密码」），或删除后用新邀请码重新注册。

## 四、隐私保护设计（本方案的核心）

| 设计 | 做法 | 目的 |
|---|---|---|
| **最小采集** | 注册只需要「昵称 + 密码」两项；**不采集手机号、邮箱、身份证号、真实姓名、学籍号** | 满足《个人信息保护法》最小必要原则；学生无需交出敏感信息即可用平台 |
| **学号解耦** | 学号由平台自动分配（如 `S2026004`），是与学籍号无关的平台内编号 | 平台内不存放学籍号，泄露风险为零；教师用线下名单与平台编号对应即可 |
| **昵称而非实名** | 界面鼓励使用昵称；班级展示（排行榜）只显示昵称 | 学生之间的可见信息不含真实身份 |
| **密码安全** | bcrypt 加盐哈希存储，任何人（含管理员）看不到明文 | 防拖库撞库 |
| **数据本地** | 成绩、错题、掌握度只存平台自身服务器数据库，不外传；AI 问答只发送题目与知识库文本，不含学生身份 | 数据不出校方控制的服务器 |
| **导出可控** | 教师可导出班级成绩 CSV 用于教学分析；导出文件由教师自行保管 | 教学必要范围内的数据使用 |
| **可删除** | 教师可物理删除学生账号及其全部学习痕迹（答题、错题、积分、会话） | 结课/毕业后可清理，不留个人信息 |

## 五、安全设计（后端已实现并验收）

| 机制 | 说明 |
|---|---|
| 邀请码空间 | `FD-` + 6 位去混淆字符（无 0/O/1/I/L），约 8.9 亿组合，无法穷举 |
| **失败限流** | 同一 IP 10 分钟内失败尝试 ≥20 次即拒绝 10 分钟（防脚本猜码）；**成功注册不计数且即时清零**——保证机房/教室几十人共用一个出口 IP 时不会误伤整班注册 |
| **人数上限** | 每个邀请码有 max_uses；采用条件更新闸门（`UPDATE … WHERE used_count < max_uses`）保证多人同时注册也**不会超发**（实测 6 并发仅 1 人成功、其余明确提示） |
| 学号唯一 | 数据库唯一约束 + 冲突自动换号重试（并发安全，实测无重复学号） |
| 昵称防护 | 长度 1–20 字；禁止含「管理员 / 老师 / admin / teacher / 系统 / 官方」等字样（防冒充身份）；渲染统一转义（Vue 模板，无 XSS 面） |
| 有效期 | 到期自动失效，需教师重新生成 |
| 鉴权 | 生成/查看/停用/删除邀请码均需教师身份；教师只能操作自己生成的邀请码（横向越权返回 403）；未登录一律 401 |
| 自动化验收 | `tools/invite_check.py`：生成→注册→自动登录→新账号可用性→无效码/弱口令/超长昵称/冒充昵称/停用码/用完码全部正确拒绝→越权拦截→清理，共 20 余项断言 |

## 六、常见问题

**Q1：一个班 50 人在同一间机房注册，会被限流吗？**
不会。限流只统计**失败**尝试，成功注册即清零；邀请码本身限制总人数（如 60 人）。

**Q2：邀请码被学生转到校外怎么办？**
三点防护：① 设较小人数上限（如班级人数 +5）；② 设较短有效期（如 7 天）；③ 发现异常可立即**停用**该码；已注册账号可逐个停用/删除。此外注册时不会额外采集信息，即使外流也只占用名额，不产生隐私风险。

**Q3：需要学生用真实学号吗？**
不需要，也不建议（学号属个人信息）。平台内编号 + 线下名单对应即可满足教学分析。

**Q4：教师怎么知道「S2026007」是谁？**
线下建立一次对应表（如按注册顺序/座位表），或让学生把昵称写成「学号后三位+姓」（如「07张」）——是否这样做由学校自行决定，平台不强制。

**Q5：结课后数据怎么处理？**
账号管理页可删除单个/整批学生账号（连带学习数据）；也可保留成绩 CSV 后清空账号，平台内不留个人身份信息。

**Q6：能否用学校统一身份认证（如智慧校园账号）登录？**
可以扩展（已列入后续规划：接入院校统一认证 SSO），当前版本为避免采集学籍信息，采用邀请码 + 平台内编号的方案。
